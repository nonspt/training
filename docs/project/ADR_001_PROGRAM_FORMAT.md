# ADR 001：分日、逐组与组合编排的数据兼容

2026-10-16，1.1.0。已完成本地实现和验证，用户已授权上传发布。用户授权的范围是不同训练日方案、逐组目标、超级组与循环组。

## 决策与影响

复用 React/TypeScript、TrainingService、Repository、IndexedDB 和既有 PWA；没有新增依赖。新增 domain/program 处理方案、组参数、复制及整体排序，calendar 提供共用日期运算；plans 的既有导出保留。UI 复用动作库、滑块、胶囊、弹窗和虚线路由。

Plan 可包含 dayPlans，每个选中星期对应一个有名称的独立方案；不启用分日时沿用 items。PlanItem 可包含与 sets 等长的 setTargets，保存热身/正式类型及每组时长、次数、重量、用力和休息。组合在各方案的 groups 中引用连续动作，超级组限两个，循环组为 2–10 个，轮数为 1–10。组合内以动作间休息、轮间休息为准，成员独立的组间休息暂不执行；拆分后恢复这些设置。

buildStages 按实际训练日期选择方案，再逐轮展开组合；首页、预计用时和跟练使用同一结果，不合并任何执行段。跟练快照和记录保存 dayName，快照另保存每段组类型与轮次。修改计划不会重写已开始的快照。

## 升级与恢复

IndexedDB 的物理数据库仍为 training-follow-db v1，state store 不变；应用内 State.schemaVersion 支持 1、2。旧计划/草稿/记录按原值读取。普通旧数据继续保持 v1，首次保存新结构时通过原有 readwrite 事务升级为 v2，revision 递增。已经为 v2 的状态不会自动降级，包括删除数据后的空状态。

旧版应用会拒绝 v2，避免把新增字段静默丢弃。新版导出 v2 备份，仍接受 v1/v2 备份；仍按校验→预览→确认合并，冲突保留本机、失败事务回滚；文件上限仍为 5 MB。

首次写入新结构之前，通过 MessageChannel 查询当前离线 worker 是否支持 v2。存在旧 worker 时拒绝该次保存，提示取消编辑并在设置中更新应用，原数据与 revision 不变。旧模式训练仍可使用；有未结束草稿时继续沿用原来的禁止更新规则。新 worker 确认支持后才写入新格式，避免联网读取新代码、离线回退到旧代码而无法读取新数据。没有改变导航/静态资源缓存策略，也不强制接管或清理用户数据。

回滚代码时必须保留 v2 数据读取与 worker 格式确认能力，不可直接部署 1.0.5 后手工把 schemaVersion 改为 1。升级前的 v1 备份可以供旧版恢复，但不包含升级之后的新结构与记录。新版备份应使用 1.1.0 及以上恢复；不以清库回滚。

## 验收入口

pnpm test、pnpm test:program、pnpm test:program-upgrade。升级专项使用独立随机端口服务与隔离浏览器，模拟不支持格式确认的旧 worker，不修改用户的预览资源、数据或缓存。实际结果见 VALIDATION_REPORT。
